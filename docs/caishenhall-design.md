## 1. 背景与目标

在现有「祈福」之后新增一个常驻 Tab——**财神殿**。页面以殿宇为背景、财神像居中，用户可在此**点长明灯、上一炷香**，作为民俗文化展示与静心计时功能。

核心约束来自历次审核结论：
- 「供奉财神」四档付款（2026-09-27）→ **封建迷信拒审**
- 求签内嵌付费加次数（2026-10-05）→ **审核不通过**
- 四档打赏 + 捐赠明细页（2026-10-05）→ **过审**

差别只有一条：**钱和"祈福行为"绑没绑在一起**。因此本方案严格遵循——**灯与香绝不售卖，付费只走装扮/打赏**。

---

## 2. 合规红线（必守）

| ❌ 禁用 | ✅ 替代 |
|---|---|
| 供奉、上供、贡品、香火、灯油、功德 | 装扮、点亮、静心、一炷香、陪伴 |
| 保佑、加持、消灾、招财进宝、转运改运 | 记录、许愿、陪伴、氛围 |
| 财神实现你的心愿 | 写下今日心愿（走已有心愿墙） |
| 购买香 / 购买灯 | 获取心意值（每日行为） |
| 烧香拜佛 | 传统文化体验 / 静心计时 |

提审定性说明（建议写入提审材料）：
> 财神殿为民俗文化展示与静心计时功能，点灯上香为免费的界面互动，不售卖任何供奉类虚拟物品；付费仅用于解锁界面装扮及支持开发者。

---

## 3. 方案选型

| 方案 | 形态 | 合规风险 | 仪式感 | 商业空间 |
|---|---|---|---|---|
| A. 灯香全免费 + 装扮付费 | 灯/香靠每日行为获取，付费只买殿内皮肤 | 低 | 强 | 中 |
| B. 静心化（去宗教语义） | "一炷香=专注计时"、"长明灯=陪伴灯"，财神殿只是视觉主题 | **最低** | 中 | 中 |
| C. 直接卖灯卖香 | ❌ | **必拒** | 强 | ❌ |

**采用 A + B 融合**：交互形态用 A（真的能点灯、真的能上香），语义文案用 B（中性化表述），付费只走装扮/打赏。

### 3.1 上香实现（分两版）

- **V1 轻量版（首版上）**：点香 → 约 2.5 秒燃烧动画（香体高度递减 + 青烟粒子）→ 完成记一次"财源广进"飘字，不做真实后台计时。
- **V2 沉浸版**：真实计时 5/15/30 分钟，前台倒计时，退后台暂停并本地保存，回来续上。

当前按 **V1 + 常驻 Tab（在"祈福"之后）+ 装扮分档解锁** 落地。

## 4. 页面结构

```
财神殿 Tab（全屏沉浸，不加 BouncePage 回弹）
├─ 殿宇背景层：朱红渐变 + 殿柱/匾额"財神殿"/帷幔 + 金色光晕
├─ 财神像居中： deities/1~5.png（用户当前所选神像）
├─ 左侧：长明灯（可点亮/熄灭，点亮后常驻到次日 0 点）
├─ 右侧：香炉（incense_burner.png）
│        └─ 点击 → 上一炷香 → 香体燃烧动画 + 青烟粒子 + 财运相伴
├─ 底部：心意值条 / 今日已上香 N 支 / 连续点亮 N 天
└─ 财神像点击 → 写心愿（复用已有 CloudService.createWish）
```

> V1 视觉可用渐变 + Shape 矢量先搭，美术图（神像/香炉/灯）后补。

## 5. 灯与香的"免费"获取机制

引入 **「心意值」**（非"香火值"，避开宗教词），靠每日行为产出，**永不售卖**：

| 行为 | 产出 |
|---|---|
| 每日首次进殿 | +5 |
| 每日签到 | +3 |
| 磕头每 10 次 | +1 |
| 木鱼每 100 次 | +1 |
| 完成一次上香（一炷香到底） | +2 |
| 每日上限 | 20 |

消耗：**点一盏灯 −2，上一炷香 −3**。用完即止，**不弹任何付费框**（过审关键：屏幕上看不到"钱换香"的因果链）。

## 6. 商业化开口（唯一付费点）

**只卖"殿内装扮"，一次性买断，不新建消耗型商品**：

| 装扮 | 内容 | 解锁方式 |
|---|---|---|
| 灯样式 | 宫灯 / 莲灯 / 琉璃灯 | 打赏 ¥8 解锁 |
| 香炉 | 青铜 / 三足 / 鎏金 | 打赏 ¥18 解锁 |
| 殿宇主题 | 朱红昼殿 / 金辉 / 夜殿 | 打赏 ¥88 解锁 |
| 尊享 | 水晶殿 | 打赏 ¥888 全解锁 |

- 复用现有 `TIP_PRODUCTS` 四档，**AGC 不新增商品**，商品名保持"支持·心意/祝愿·顺遂"等中性名。
- 文案统一：**"支持作者后解锁殿内装扮样式 · 装扮仅为视觉效果，不具备任何祈福效力"**。
- 解锁逻辑：打赏某一档即解锁该档及更低档对应装扮组（越买越多，¥888 解锁全部尊享）。

## 7. 数据模型

独立 preference 文件 `caishen_hall_prefs`（与卡片进程共享时须 `removePreferencesFromCache` 后读，遵循现有跨进程铁律；V1 建议卡片不接入）。

```ts
interface HallState {
  lastDate: string        // 上次进殿日期（跨天重置）
  todayHeart: number      // 今日已得心意值
  heart: number           // 心意值余额
  lampLit: boolean        // 今日长明灯
  lampStreak: number      // 连续点亮天数
  sticksToday: number     // 今日上香支数
  sticksTotal: number
  focusSecToday: number   // 今日上香时长
  focusSecTotal: number
  decor: string[]         // 已解锁装扮 id
  activeLamp: string      // 当前使用灯样式
  activeBurner: string    // 当前使用香炉
  activeTheme: string     // 当前使用主题
}
```
